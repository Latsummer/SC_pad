# 蓝图品质属性接入

## 与现有配方的区别

原有卡片数据只记录材料种类、槽位、用量、制造时间。新阶段采集的是制造材料的品质 Q（页面范围通常为 0–1000），不是矿物的采矿抗性、密度或扫描特征。槽位是否影响属性由该蓝图页面明确显示的影响项决定，不能因为材料相同就跨配方套用。

数据分为基础成品属性、槽位品质影响规则、品质取值下的观察结果。原文与结构化字段一起保留，用 recipe_id 和原 URL 定位，中文显示名不作为主键。

## 已做的公开页面核对

在 `4.10.2-live.12913470` 的公开英文界面检查了：

- C54 弹匣：页面说明最低品质 0、提高品质没有效果；不应显示制造属性加成滑块。
- C54 Scorched 冲锋枪：框架和枪托影响后坐力，枪管影响伤害与射速。最低／基础／最高预设有不同的成品结果，多个槽位影响同一属性时不能简单相乘；DPS 也不是单独一个材料倍率。
- Inquisitor Arms Base：防护槽影响减伤，保温槽影响温度。单独把防护槽设为最高品质时，抗性变化但温度不变。伤害倍率与伤害减免是不同指标，不能将 ×0.70 当成“70% 减伤”。

这些是代表样本，不构成所有类别的统一公式。成品显示的舍入精度有限。

## 分阶段推进

1. 当前助手保留旧列表导出，另加“采集品质预设／记录当前详情／导出属性”，先收集弹匣、武器、护甲三个样本。用 Inspector 校验身份、材料、预设覆盖及品质范围。
2. 已加入用户启动的批量打开详情、IndexedDB 检查点和失败重试，默认 10 个。先验证英文小批量导出，再扩大；普通配方只记录明确说明，不反复采不存在的滑块。卡片以完整可见文本及同文出现次序定位，要求批次内列表顺序与内容不变；同文卡片分别打开，配方身份最终取详情 URL。
3. 已建立 `data/scmdb-blueprint-quality.json` 和 64 个带内容摘要的 `dist/blueprint-quality/details-*.json`，列表使用独立轻量配方字段，不加载全部属性。按公开配方 ID 保留 1618 个物品，同名条目不合并；旧卡片规范文件保留用于追溯。
4. 已新增“制造详情”弹窗，展示四组实际采集预设、原始属性和当前预设结果、逐槽品质与规则；射击模式分别分组。手机分“成品属性／材料品质”两页。69 个固定品质配方明确显示无品质影响，不提供无意义的预设。现已提供独立槽位滑块与数字输入，估算与实测预设明确区分。
5. 逐类别验证最终公式：武器射速／伤害／DPS／后坐力，护甲伤害减免与温度，飞船组件的各自属性。每次打开详情按最低／基础／中点／最高逐项检查材料倍率与成品公式；匹配项提供明确标注的本地估算，其余保留观察结果。混合槽位估算仍应继续补充独立实测验证，不声称已在游戏中验证。

不得把奖励池概率、装备基础属性、矿物采矿属性和制造品质混为一谈，也不把某一件物品的取样曲线推广到整个分类。

采集助手同时支持自由模式的数字框和吸附模式的滑块，按槽位选择一个可写控件并恢复原品质。批次导出中的 `automation_runs[].timings` 区分打开、采样、返回耗时；返回列表仍需等待 SCMDB 自身渲染。批量期间暂停自动列表扫描，定位校验采用不触发布局的文字签名。

## 重新构建和定期更新 SOP

1. 在英文页面按当前版本采完整详情，核对不同 ID、完成数、失败数和未分类特殊物品；无详情不能自动当作无品质影响。保留原始 JSON，不手改。
2. 压缩归档放入 `imports/scmdb/blueprint-details/`，附来源版本与哈希 manifest。当前默认基线固定为 `scmdb-blueprint-details-2026-10-21T10-26-31-626Z.json.gz`，不按 mtime 自动选。
3. `make blueprint-quality-build` 从固定归档生成规范详情、独立中文报告、64 个按需分片与网页配方目录。检查新归档可先运行 `python3 tools/build_blueprint_quality_data.py --capture /path/capture.json.gz` 再运行 `python3 tools/build_blueprint_site_data.py`；确认后更新工具默认基线常量，保证 CI 可复现。跨补丁版本要求先更新矿物／翻译基础版本，不用翻译版本冒充采集版本；同补丁不同 build 保留两者真实版本。
4. 规则分为倍率端点、供电阶梯和未验证原文。此次 5098 条倍率端点只记录范围，不推断所有成品公式；150 条 Power Pips 阶梯独立解析；3 条缺 Base 且带 ⚠ 的减伤规则保留异常状态。网页四预设数值直接来自采样，不通过通用插值重算。
5. 检查 `data/scmdb-blueprint-quality.translation-report.md`；修改名称／槽位／属性中文应改维护表再构建。新目录与卡片由导出映射、槽位、材料、数量交叉验证，任一不一致拒绝构建。同名不同 ID 不合并，不按英文标题猜身份。
6. 运行 `python3 tools/test_blueprint_quality_data.py`、`python3 tools/check_scminer_site.py`；检查桌面和约 430×932 手机的预设、固定物品、阶梯规则和异常提示、来源任务入口。修改页面或样式后运行 `make site-cache` 更新 Service Worker 和脚本 URL（`make blueprint-quality-build` 已包含此步）；按用户授权提交／发布。

完整详情中的初始手动品质不作为四预设计算规则。只把明确来源的基础／最低／中点／最高观察值部署，成品射击模式与原始单位保留。原始 JSON 解压 58 MB，当前按需分片合计约 5.6 MB、单片最大约 139 KB。首次打开详情需联网；之后由站点 Service Worker 缓存，不宣称未访问的所有详情均离线可用。

额外来源检查：75 个电源的基础预设存在供电槽数字框 0、滑块 1 的不一致，网页保留观察值并提示；基础预设不代表所有槽位零加成。规范文件记录每个预设的 `quality_issues`，不能静默夹取一个值来重算成品。

## 品质滑块估算维护

计算在 `dist/blueprint-quality-model.js`，不改写采集数据。槽位倍率按明确端点作线性估算，同属性倍率以 `1 + Σ(m − 1)` 合并，DPS 使用伤害与射速两个合并倍率的乘积；减伤先作用于 `1 − 原始承伤倍率`，再换回承伤倍率。供电格数按各槽位区间增量相加。

这些是与当前四预设相容的估算模型，不是仅凭四点证明的任意组合游戏公式。每个材料效果先匹配已采倍率（容许来源三位小数舍入），每项成品再匹配全部预设（容许显示末位舍入与原始值精度）；任一不符不计算该项。异常规则不补齐。相同名属性保留射击模式上下文，不跨配方套用。估算统一标识，未匹配成品项显示“规则未核对，保留预设值”。

验证命令：`node tools/test_blueprint_quality_model.cjs` 覆盖全部 6265 个来源快照，另测混合槽位、供电边界、异常拒绝；`node tools/test_blueprint_quality_ui.cjs` 覆盖预设与异步载入。新增规则先用独立槽位／混合品质公开样本核对，然后扩展映射及回归样本，运行 `make site-cache`。
