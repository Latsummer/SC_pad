# 任务采集快照

在仓库根目录执行 `make scmdb-missions-capture`，打开生成的
`scminer-local/capture-tools/missions.html`，按说明安装书签。
可直接在桌面浏览器打开本地 HTML；可选的 `make scmdb-serve` 只是提供安装页，
书签安装后不需要本机服务继续运行。助手脚本保存在书签网址本身，新版本需要重新保存书签。

## 已归档基线

- `scmdb-public-missions-2026-10-20T11-03-16-308Z.json.gz`：用户最终英文采集，原始 JSON 无修改压缩保存，1765 个列表任务均有详情及完成标识。
- 同名 `.manifest.json`：原始／压缩文件 SHA-256、大小、来源、时间和标签统计。
- 采集文件本身没有游戏版本，manifest 的 `game_data_version: 4.10.2` 来自用户确认的补丁版本；不声称完整 build 号，也不以翻译表版本代替。当前只能证明本次列表已遍历，不证明隐藏活动、合并变体或折叠内容完整，不据此判定任务移除。
- 原始快照不放进 `dist/`，不随 PWA 下载。解压示例：`gzip -dc scminer-local/imports/scmdb/missions/scmdb-public-missions-2026-10-20T11-03-16-308Z.json.gz > /tmp/scmdb-missions.json`（仓库根目录执行）。

## 后续数据组织

原始快照与规范数据分开。后续离线导入器从 JSON／JSON.GZ 读取，生成按任务稳定标识组织的规范字段、共享声望表／奖励池、翻译匹配报告与版本差异报告。网站再从规范数据生成精简列表索引和按需详情分片。

版本清单需要确认源游戏版本、LIVE/PTU、筛选与事件范围及采集失败项。部分采集仅更新已见任务；只有范围可比的完整列表才能提出“疑似移除”，保留历史记录。不得按显示名称合并任务，保留原始 `debug_name`（包含尾部空格）并验证哈希碰撞。翻译歧义保留英文，生成待确认报告。

## 助手行为

将导出的 `scmdb-public-missions-*.json` 放在本目录，并记录采集页面显示的游戏版本。
格式为 `scmdb-public-missions-capture-v1`，按公开任务标识和 LIVE/PTU 分组，保留
列表文本及 Overview、Combat、Requirements 的多次详情快照、区块、链接和提示。
只对相同内容去重，不把同名任务合并；不采集 Community、用户输入或登录信息。
v3 的 Calculator 快照在 `calculator_basis` 中保存奖励标签／值、各等级的 XP 差额和共享规则提示，
不采集任务次数列，不操作人数控件。XP 差额不是累计 XP 门槛，解析时不能混用。
v2 起支持中文标签并保存独立的 `tab_key`；`page_language` 是 HTML 声明，不能证明文本为英文。
`helper_version` 记录助手版本，`automation_runs` 保存批次完成数和失败项，
`completed_mission_keys` 保存已完整遍历公开标签的任务标识（不等于完整性证明）。

详情标签计数不代表其折叠内容已全部展开。用户点击“自动采集详情”后会限速逐个打开
当前列表卡片、切换公开标签、尝试展开标准 disclosure 并关闭详情；v4 默认每批 100 个。
可停止，再启动跳过已完成项；不自动翻页、不访问 `/data/`，不保证
全量任务覆盖；建议在关闭或离开前导出。根目录 `make missions-build` 已提供独立任务规范化与网站数据构建，不参与蓝图构建。

v3 批量期间缓存卡片索引，只读当前详情，按连续 DOM 稳定样本等待；面板显示实际速率和预计剩余时间。离线稳定样本的等待预算不等于真实浏览器全量耗时。

v4 使用 Worker 计时器（CSP 不允许时回退），每25个完成任务、停止或批次结束保存到本浏览器 IndexedDB。
恢复需手动点击“恢复上次进度”，并自行核对游戏版本／语言／LIVE/PTU 未变；相同来源键的下一次保存会覆盖旧检查点。
保存仅含助手采集的数据和完成标识，不读取站点内部存储。后台仍可能被浏览器冻结或操作系统休眠暂停。
完成后默认触发一次 JSON 下载，若浏览器拦截，保留页面手动导出。
